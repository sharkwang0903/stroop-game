# Stroop 顏色衝突

一個使用原生 HTML、CSS 與 JavaScript 製作的 Stroop 顏色判斷小遊戲，提供一般模式、專家模式、困難模式與極限生存四種玩法。

一般與專家模式要求玩家忽略中文字的意思，選擇文字實際顯示的顏色；困難與極限生存則會依畫面提示，隨機要求判斷字體顏色或文字內容。

## 如何執行

本專案不需要安裝套件、執行 npm 或啟動伺服器。

1. 開啟專案資料夾。
2. 直接雙擊 `index.html`。
3. 使用瀏覽器即可開始遊玩。

如果修改檔案後沒有看到最新畫面，可以在瀏覽器按下 `Ctrl + F5` 強制重新整理。

## 專案檔案

### `index.html`

負責整個網站的 HTML 結構，包含：

- 首頁與遊戲介紹
- 四種模式的選擇入口
- 60 秒挑戰與 20 秒生存倒數的遊戲進行畫面
- Stroop 題目顯示區
- 一般、專家、困難模式的四個答案按鈕，以及極限生存使用的兩個額外按鈕
- 遊戲結果頁
- 斯特魯普效應科普內容

這個檔案也會依序載入樣式表與所有 JavaScript 檔案。

### `style.css`

負責網站的所有視覺與響應式排版，包含：

- 首頁、遊戲畫面與結果頁的版面
- 黑、白、灰為主的極簡介面
- 紅、藍、綠、黃四種遊戲顏色
- 圓形答案按鈕、陰影、hover 與 pressed 效果
- 一般模式的彩色答案按鈕
- 專家模式的白底、灰框無色答案按鈕
- 困難模式的動態問法與無色答案按鈕
- 極限生存專屬的六顆白底圓形按鈕、2 × 3 排列與彩色選項文字
- 題目文字、計時器與結果資料的尺寸和間距
- Desktop、Tablet、Mobile 的 RWD 調整
- 防止手機產生橫向捲軸

### `game.js`

負責所有與輸入裝置無關的遊戲核心邏輯，包含：

- 開始、重新開始與結束遊戲
- 以共用的 `mode` 狀態切換四種模式
- 保留前三種模式的 60 秒整數倒數，並接上極限生存的獨立時間設定
- 產生 Stroop 題目
- 困難模式中平衡且隨機地切換字體顏色題與文字內容題
- 控制約 25% 一致題與 75% 衝突題
- 平衡紅、藍、綠、黃四種正確答案的出現次數
- 判斷玩家答案是否正確
- 記錄總題數、答對數與答錯數
- 計算準確率
- 記錄每題反應時間
- 計算正確回答的平均反應時間
- 記錄目前連續答對與最高連續答對
- 整理並顯示結果資料
- 極限生存結束後顯示實際生存時間

`game.js` 不直接綁定滑鼠或手機觸控事件。它提供共用的 `submitAnswer(color)`，讓桌面與手機控制程式使用同一套答案判定邏輯。

### `survival-mode.js`

只負責極限生存模式的專屬規則，包含：

- 20 秒初始時間、答對增加 2 秒與 20 秒上限
- 每題產生六個具有「文字內容」與「字體顏色」的 Stroop 干擾選項
- 依目前問法決定選項的答案判定值
- 保證六個選項中，只有一個選項符合本題正確值

這個檔案刻意與 `game.js` 分開，讓前三種已穩定運作的模式不必承擔生存模式的選項生成細節。

### `desktop-controls.js`

只負責桌面裝置的答案操作，包含：

- 監聽滑鼠點擊答案按鈕
- 處理滑鼠按下時的視覺狀態
- 防止滑鼠雙擊連續提交兩題
- 忽略由手機觸控產生的相容性 click 事件

玩家點擊答案後，這個檔案會呼叫 `game.js` 提供的 `StroopGame.submitAnswer(color)`，不會自行判斷答案。

### `mobile-controls.js`

只負責手機與觸控裝置的答案操作，包含：

- 處理 touch／pointer 輸入
- 使用 `pointerId` 避免同一次觸控重複提交
- 防止 double tap 誤答下一題
- 防止觸控後再次觸發 click
- 防止長按選單與事件穿透
- 處理觸控按壓狀態

觸控答案後，這個檔案同樣呼叫 `StroopGame.submitAnswer(color)`，所有遊戲判定仍由 `game.js` 完成。

### `main.js`

負責網站初始化與非答案類的共用頁面操作，包含：

- 初始化 `game.js`
- 初始化桌面控制模組
- 初始化手機控制模組
- 綁定「開始挑戰」
- 將玩家選擇的四種模式之一傳入共用的遊戲啟動函式
- 綁定「再玩一次」
- 綁定「回到首頁」

它是 HTML 畫面與各 JavaScript 模組之間的初始化入口。

## 模組互動方式

答案提交的基本流程如下：

```text
玩家點擊或觸控答案
        ↓
desktop-controls.js 或 mobile-controls.js
        ↓
StroopGame.submitAnswer(color)
        ↓
game.js 判斷答案、記錄資料並產生下一題
```

桌面與手機只負責接收不同的輸入方式，核心玩法不會重複實作。

四種模式共用同一套 `game.js`。只有極限生存的時間常數與六選項生成交由 `survival-mode.js`；桌面和手機仍使用原本的事件代理，因此不必為六個按鈕複製一套操作程式。

## 遊戲規則摘要

- 一般、專家與困難模式每局固定 60 秒，維持整數倒數。
- 一般與專家模式要選擇中文字實際顯示的顏色。
- 一般模式使用彩色圓形答案按鈕。
- 專家模式使用完全相同的白色圓形按鈕，只以黑色文字區分答案。
- 困難模式沿用無色按鈕，並隨機詢問字體顏色或文字內容。
- 極限生存從 20.0 秒開始，答對增加 2.0 秒、最多回到 20.0 秒；答錯不加秒也不額外扣秒。
- 極限生存沿用困難模式兩種問法，並用六個白底圓形按鈕加入選項文字與字色的雙重干擾。
- 極限生存每題只有一個正確選項，倒數歸零時立即結束並記錄實際生存時間。
- 題目約 25% 為字義與字色一致，75% 為字義與字色衝突。
- 四種正確答案透過隨機洗牌袋保持大致平均。
- 遊戲中不顯示答對、答錯、分數或準確率。
- 時間結束時，尚未作答的題目不會被計入。
- 平均反應時間只計算答對的題目。

## 四種模式快速測試

1. 開啟首頁，依序進入一般、專家、困難模式，確認仍為 60 秒、四個選項，且按鈕外觀與原本一致。
2. 在困難模式多答幾題，確認問法會在「字體的顏色」與「顏色的文字」之間隨機切換。
3. 進入極限生存，確認初始顯示 `20.0 秒`、畫面有六顆 2 × 3 排列的白底圓形按鈕，按鈕中文字帶有紅、藍、綠或黃。
4. 在極限生存答對一題，確認時間增加 2 秒但不超過 20.0 秒；答錯一題則只讓時間自然倒數。
5. 等待極限生存倒數歸零，確認立即進入結果頁，且比其他模式多顯示一項小數一位的「生存時間」。
6. 用桌機滑鼠與手機觸控各測一次；手機上確認六顆按鈕沒有重疊，也沒有橫向捲軸。
