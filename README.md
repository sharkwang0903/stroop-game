# Stroop 顏色衝突

一個使用原生 HTML、CSS 與 JavaScript 製作的 60 秒 Stroop 顏色判斷小遊戲。

玩家需要忽略中文字本身的意思，選擇文字實際顯示的顏色。例如「紅」字如果以藍色顯示，正確答案就是「藍色」。

## 如何執行

本專案不需要安裝套件、執行 npm 或啟動伺服器。

1. 開啟專案資料夾。
2. 直接雙擊 `index.html`。
3. 使用瀏覽器即可開始遊玩。

如果修改檔案後沒有看到最新畫面，可以在瀏覽器按下 `Ctrl + F5` 強制重新整理。

## 專案檔案

### `index.html`

負責整個網站的 HTML 結構，包含：

- 首頁與遊戲介紹
- 一般模式的開始按鈕
- 60 秒遊戲進行畫面
- Stroop 題目顯示區
- 紅、藍、綠、黃四個答案按鈕
- 遊戲結果頁
- 斯特魯普效應科普內容

這個檔案也會依序載入樣式表與所有 JavaScript 檔案。

### `style.css`

負責網站的所有視覺與響應式排版，包含：

- 首頁、遊戲畫面與結果頁的版面
- 黑、白、灰為主的極簡介面
- 紅、藍、綠、黃四種遊戲顏色
- 圓形答案按鈕、陰影、hover 與 pressed 效果
- 題目文字、計時器與結果資料的尺寸和間距
- Desktop、Tablet、Mobile 的 RWD 調整
- 防止手機產生橫向捲軸

### `game.js`

負責所有與輸入裝置無關的遊戲核心邏輯，包含：

- 開始、重新開始與結束遊戲
- 60 秒倒數計時
- 產生 Stroop 題目
- 控制約 25% 一致題與 75% 衝突題
- 平衡紅、藍、綠、黃四種正確答案的出現次數
- 判斷玩家答案是否正確
- 記錄總題數、答對數與答錯數
- 計算準確率
- 記錄每題反應時間
- 計算正確回答的平均反應時間
- 記錄目前連續答對與最高連續答對
- 整理並顯示結果資料

`game.js` 不直接綁定滑鼠或手機觸控事件。它提供共用的 `submitAnswer(color)`，讓桌面與手機控制程式使用同一套答案判定邏輯。

### `desktop-controls.js`

只負責桌面裝置的答案操作，包含：

- 監聽滑鼠點擊答案按鈕
- 處理滑鼠按下時的視覺狀態
- 防止滑鼠雙擊連續提交兩題
- 忽略由手機觸控產生的相容性 click 事件

玩家點擊答案後，這個檔案會呼叫 `game.js` 提供的 `StroopGame.submitAnswer(color)`，不會自行判斷答案。

### `mobile-controls.js`

只負責手機與觸控裝置的答案操作，包含：

- 處理 touch／pointer 輸入
- 使用 `pointerId` 避免同一次觸控重複提交
- 防止 double tap 誤答下一題
- 防止觸控後再次觸發 click
- 防止長按選單與事件穿透
- 處理觸控按壓狀態

觸控答案後，這個檔案同樣呼叫 `StroopGame.submitAnswer(color)`，所有遊戲判定仍由 `game.js` 完成。

### `main.js`

負責網站初始化與非答案類的共用頁面操作，包含：

- 初始化 `game.js`
- 初始化桌面控制模組
- 初始化手機控制模組
- 綁定「開始挑戰」
- 綁定「再玩一次」
- 綁定「回到首頁」

它是 HTML 畫面與各 JavaScript 模組之間的初始化入口。

## 模組互動方式

答案提交的基本流程如下：

```text
玩家點擊或觸控答案
        ↓
desktop-controls.js 或 mobile-controls.js
        ↓
StroopGame.submitAnswer(color)
        ↓
game.js 判斷答案、記錄資料並產生下一題
```

桌面與手機只負責接收不同的輸入方式，核心玩法不會重複實作。

## 遊戲規則摘要

- 每局固定 60 秒。
- 玩家必須選擇中文字實際顯示的顏色。
- 題目約 25% 為字義與字色一致，75% 為字義與字色衝突。
- 四種正確答案透過隨機洗牌袋保持大致平均。
- 遊戲中不顯示答對、答錯、分數或準確率。
- 時間結束時，尚未作答的題目不會被計入。
- 平均反應時間只計算答對的題目。
